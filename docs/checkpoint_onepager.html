Token Bias vs. Position Bias in LLM Multiple-Choice Selection

CSCI 567 project checkpoint · J. Lee · 28 October 2026 · Zheng et al., Large Language Models Are Not Robust Multiple Choice Selectors, ICLR 2024 Spotlight (arXiv:2309.03882)

1. Central claim

LLMs have a large, inconsistent preference among multiple-choice options that comes mainly from token bias — an a-priori preference for the label tokens A/B/C/D — rather than from position bias, a preference for where an option sits in the list.

2. Key experiments

Zero-/five-shot MMLU, ARC-Challenge and CSQA over 20 models (LLaMA-1/2, Vicuna, Falcon, GPT-3.5). One forward pass per prompt; a softmax over the label tokens after “Answer:” gives the prediction. Bias is reported as RStd, the standard deviation of per-label recall. Conditions: cyclic/perm (option content permuted, labels left in place), move_a–d (gold swapped to a fixed label), shuffle_both (label–content pairs shuffled), and “removing IDs” (noid), the ablation carrying the main conclusion. They then propose PriDe, which estimates a label prior from a few permuted samples and divides it out, cutting RStd ~4× for ~5% extra compute.

3. Our alternative hypothesis

A substantial part of the bias is positional, and the paper's design cannot see it.

(a) The ablation changes two things at once. “Removing IDs” deletes the labels and switches scoring from a next-token softmax over A/B/C/D to per-option likelihood, so any drop in bias is attributable to either change.

(b) Elsewhere, label and position are the same variable. We parsed the prompts in the authors' released results: in cyclic, perm and move_a–d the option text moves but the label column always reads A, B, C, D top to bottom, so “label A” and “line 1” are one regressor. If labels appear in natural order the label is a function of position; the only ways out are to break that order or delete the labels.

4. Our experiment

Rotate label order and content order independently: with content shift j and label shift k, line p shows content o[(p+j) mod 4] under label “ABCD”[(p+k) mod 4] — 16 versions in which every label occupies every position. Prompt template, scoring and data filtering stay exactly as the paper's; only ordering changes. A conditional logistic regression over each 4-alternative choice set, with label dummies, position dummies and an is_gold term, separates the two effects.

5. Status of the paper's code

Upstream is cloned read-only as a submodule pinned at 2ae2f40, with dependencies pinned to its era (transformers 4.36.2, torch 2.1.2) because current releases break it in ways that would change the label token ids we score. Reading it corrected two assumptions: scoring softmaxes over eight ids (space-prefixed and bare variants of each label, summed in pairs), not four; and the “all of the above”/“A and B” items are filtered after inference, not in the data — the authors' own lists drop 450/14042 = 3.20% of MMLU, matching their stated 3.2%. From the released result files we reproduced the Table 3 baseline exactly: Llama-2-7b-hf, MMLU 0-shot, Acc 35.80 / RStd 22.95 on the filtered 13592 items. That identifies the row and validates our metric code before any GPU time. Runs go on an A100 through an NSF ACCESS allocation.

6. Early evidence, from the authors' own data, no GPU

shuffle_both shuffles label–content pairs, so the gold label is fixed while each label's line position varies — the one released condition where position is estimable with label held fixed. Our conditional logit there (13592 choice sets) gives a position span of 0.66 logits for Llama-2-7b-hf and 0.81 for LLaMA-1-7b, against label spans of 2.78 and 0.91. For both models the position span exceeds the is_gold coefficient (0.43, 0.38): where an option sits moves the choice more than whether it is correct. With labels deleted (noid), recall still spreads 28.7 and 12.2 points across gold positions. Caveat: in shuffle_both each label keeps its original content, so label coefficients absorb content quality and are an upper bound — only the crossed design settles it.

7. Questions for the TAs

(i) Rotating labels yields an unnatural column (B, C, D, A); is comparing k=0 against k≠0 accuracy enough to bound the cost of that oddity? (ii) Our pilot indicates one version per question across many questions is as precise as all 16 per question at 1/16 the cost, since the conditional logit identifies within a choice set — is 16 versions on a ~1000-question subset enough for the within-question check? (iii) Is §6 reportable as a finding, or strictly as motivation?
